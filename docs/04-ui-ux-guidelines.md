# Express Web Platform — UI/UX Guidelines

## Experience principles
Professional, modern, clear, confident without exaggerated claims, consistent, mobile-first and accessible.

## Page hierarchy
Each page should answer: what is this, who is it for, which problem it solves, why Express Web is credible and what the next action is.

## Layout and typography
Use consistent containers, spacing and grids. Keep readable line length and semantic headings. Maintain a limited type scale and verify Serbian/German glyphs and wrapping.

## Colour and actions
Record actual tokens after audit. Maintain contrast, one dominant action colour and semantic status colours. Primary CTAs represent one main page action; labels describe the outcome, not “Click here”.

## Forms
Ask only necessary information, use visible labels, explain optional fields, provide nearby errors, preserve data after recoverable errors, prevent duplicate submission and explain consent/privacy.

## Hero standard
One primary promise, concise support text, one primary CTA, optional secondary CTA, restrained visual support and immediate credibility where useful. Avoid long service lists and competing actions.

## Blog standard
Readable structure, useful image/alt, internal links, related content and a context-appropriate CTA. Educational posts may use a low-pressure invitation to comment or contact.

## Pricing standard
Show inclusions, exclusions, variables, recurring costs and next steps. Distinguish templates, custom work, hosting, maintenance and optional services.

## Motion
Motion supports understanding, respects `prefers-reduced-motion`, avoids layout shifts and is tested on mobile.

## Responsive/accessibility verification
Test narrow/common mobile, tablet, laptop, wide desktop, long translations, keyboard navigation and zoom. No keyboard traps, missing labels, invisible focus, empty controls or inaccessible dialogs.

## Design token audit
Record colours, fonts, scale, spacing, radii, shadows, breakpoints, containers, button/form/card variants and animation utilities; approve them as the canonical design baseline.
